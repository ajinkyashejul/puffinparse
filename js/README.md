# liteocr (Node.js / TypeScript)

One API for every OCR / document-parsing provider — Reducto, Extend, LlamaParse, Mistral, Azure,
Textract, Gemini and more — from Node.js. This package is a thin typed wrapper over the LiteOCR Rust
core, loaded as a native addon (`crates/liteocr-node`, built with napi-rs). Switching provider is a
one-string change.

Full reference: [`website/pages/typescript.md`](../website/pages/typescript.md) (published at
`/docs/typescript/`).

## Quickstart

```bash
# from a clone of the repo (prebuilt binaries are not on npm yet; needs Rust + Node 18+)
cd js
npm install
npm run build            # release build of the addon -> liteocr.<platform>.node + native.js
export LLAMA_API_KEY=... # or REDUCTO_API_KEY, EXTEND_API_KEY, ...
```

```ts
import { parse, extract, Router, listModels, estimateCost, UnsupportedModelError } from 'liteocr'

const doc = await parse('invoice.pdf', { model: 'llamaparse/cost_effective' })
console.log(doc.markdown)
console.log(doc.pages[0].blocks.map((b) => [b.type, b.bbox]))
console.log(doc.costUsd, doc.latencyMs)

// Bytes need a filename (it sets the document type); URLs go straight to the provider.
await parse(fs.readFileSync('scan.png'), { filename: 'scan.png', model: 'mistral/ocr-latest' })
await parse({ url: 'https://example.com/a.pdf' }, { model: 'reducto/standard', pages: '1-3' })

const inv = await extract<{ total: number }>('invoice.pdf', {
  model: 'reducto/extract',
  schema: { type: 'object', properties: { total: { type: 'number' } } },
})

const router = new Router({ models: ['reducto/standard', 'llamaparse/agentic'], strategy: 'ordered' })
await router.parse('contract.pdf')
router.stats()

listModels('extract')
estimateCost('reducto/standard', 100)   // USD at list price
```

Errors reject as `LiteOCRError` subclasses (`AuthenticationError`, `RateLimitError`,
`BadRequestError`, `ProviderError`, `TimeoutError`, `UnsupportedModelError`, `InputError`,
`NetworkError`) whose `kind` is the core `ErrorKind` and whose `message` is the provider's own.

## Layout

| Path | What |
|---|---|
| `index.js` | The public API: argument validation, request building, camelCase conversion, error mapping. |
| `index.d.ts` | Hand-written typings matching `docs/SPEC.md` §4–6. Keep it in sync with `crates/liteocr-core/src/types.rs`. |
| `native.js`, `native.d.ts`, `*.node` | Generated by `npm run build` (git-ignored). |
| `test/unit.test.js` | Offline tests (`node:test`), including end-to-end calls against a local mock provider. |
| `test/live.test.js` | One real LlamaParse call; skipped unless `LITEOCR_LIVE_TESTS=1` and `LLAMA_API_KEY` are set. |
| `test/types.ts` | Compile-only checks for `index.d.ts` (`npm run typecheck`). |

## Develop

```bash
npm run build:debug      # faster debug build of the addon
npm test                 # offline; the live test reports as skipped
npm run typecheck        # tsc --noEmit over index.d.ts + test/types.ts
LITEOCR_LIVE_TESTS=1 LLAMA_API_KEY=... node --test test/live.test.js   # costs one LlamaParse call
```

In the monorepo, point cargo at the shared target dir to avoid a second build tree:
`CARGO_TARGET_DIR=../target npm run build`.

## Releasing prebuilt binaries (plan, not wired yet)

The `napi.targets` list in `package.json` is the platform matrix. The release flow napi-rs expects:

1. Build `npm run build -- --target <triple>` on each runner (linux x64/arm64 gnu, macOS x64/arm64,
   windows x64) and upload the `liteocr.<platform>.node` files as artifacts.
2. In one publish job, `napi create-npm-dirs` then `napi artifacts` to move each binary into
   `npm/<platform>/`, and `napi prepublish -t npm` to publish the per-platform packages
   (`liteocr-linux-x64-gnu`, ...) and add them as `optionalDependencies` of `liteocr`.
3. `npm publish` with provenance (`id-token: write`, npm trusted publishing), so no long-lived
   `NPM_TOKEN` secret is needed.

The generated `native.js` loader already looks for `./liteocr.<platform>.node` first and then the
`liteocr-<platform>` package, so the same code works from a source build and from npm. The build
matrix is stubbed in `.github/workflows/release.yml` (`node-addon` job); publishing is not.
